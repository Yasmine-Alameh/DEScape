A good cipher hides every pattern: changing one single bit of the message or of the key should change about half of the 64 output bits, and the change should spread quickly through the rounds. Pick a bit, flip it, and watch DES run twice: once with the original values, once with the flipped bit.

{% icon "cake" %} Birthday attack: why a 64-bit block is too small

The birthday paradox. In a room of only 23 people, there is already a 50% chance that two share a birthday, even though there are 365 days. Repeats appear after about √(number of possibilities) tries, not after all of them.

Applied to DES. A block cipher turns each 64-bit block into one of 264 possible outputs. Encrypt enough blocks with the same key and two ciphertext blocks will repeat after about √264 = 232 blocks, which is only about 32 GB of data.

Why it matters. In CBC mode, a repeated ciphertext block leaks the XOR of the two plaintext blocks behind it. The Sweet32 attack (2016) used exactly this to recover secret cookies from long HTTPS and VPN connections that still used 64-bit block ciphers (DES/3DES). AES uses 128-bit blocks, so repeats only appear after about 264 blocks.

Try it with real DES

232 blocks is too many for a browser, so we shrink the block: DES encrypts message after message under a random key and we keep only the first n bits of each ciphertext. We stop at the first repeat.
